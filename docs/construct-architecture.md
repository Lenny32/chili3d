# Construction geometry architecture

Construction objects are document nodes, outside the solid-producing feature list. Their IDs remain stable across edits, save/load and undo/redo. A definition stores source references and parameters; evaluated geometry is derived state and never serialized. The node exposes an explicit `Result` so a missing source does not leave a plausible stale plane, axis or point.

Source references name origin geometry, another construction node (and optionally a UCS member), or a sub-shape of a document node. Tracked topology IDs are authoritative. On untracked primitives, a unique analytic surface/circle or bounding-box corner may be matched by its semantic role across dimension edits. Other untracked shapes require their captured index and geometric fingerprint to agree; a changed or ambiguous source is invalid rather than replaced by a nearby face or edge. The resolver returns world geometry. A construction node converts external sources into its parent frame before evaluation, then applies the parent and its own transform once; fixed and global-origin references are defined in that local frame. Display size affects rendering only.

Evaluation walks the dependency graph from each consumer back to its sources; edited datum cycles are rejected before history records them. A construction node may reference an upstream body state through a captured feature index. The exact historical shape and IDs are required; an unavailable state never falls back to a later body shape. During feature replay, a datum reference to a later position of the active body is invalid. Dependencies are invalidated on definition, shape, transform and tree changes, and evaluated geometry is cached outside active body replay. Deletion and undo restore nodes and dependent results through document history. Sketches and revolve features retain the construction node ID and re-resolve it at evaluation time rather than persisting only a coordinate copy. A hidden construction node remains a valid source.

Supported associative snaps are an edge start, end, midpoint or analytic circle center; vertex references use tracked incident edges when possible. Construction points also appear in point snapping with their datum ID. A UCS exposes its XY/YZ/ZX planes and X/Y/Z axes by stable member names; its right-handed orthonormal frame has explicit local/world point conversion functions.

Path segments are stored in selection order, with an optional whole-path reversal. Consecutive endpoints must connect. Position is measured in geometric arc length rather than curve parameter. A single straight path extends beyond finite ends; curved paths and chains reject unsupported extension. On a closed path the seam is the source curve's first parameter, and a normalized position of one returns the same location. At a sharp corner, plane creation requires branch `0` for the incoming tangent or `1` for the outgoing tangent. To Object placement searches supported projections and rejects equally close distinct positions, including a circle center's infinitely many solutions. Orientation choices, baseline axes and solution indices are part of the definition so rebuilds do not silently flip or switch solutions.
